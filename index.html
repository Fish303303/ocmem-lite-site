为什么再造一个记忆插件

大多数记忆插件每轮都塞一堆检索结果，或者带个几百 MB 的向量模型。OCMem 走的是反方向。

01AI 抽取，规则兜底

每条消息交给一个小模型判断有没有长期偏好，抽出来存好；调用失败才退回本地规则，绝不影响对话。

02固定大小摘要

最多 6 条当前主题的事实写成托管区块，跟着系统提示走，不用额外工具调用、不用向量检索。

03主题分组

只展开当前主题（coding / computer / work / life），其他主题只显示数量，一行带过。

04按需检索

一个 memory 工具搞定 search / list / forget，其他情况一律不打扰模型。

实测成本：每次多 90 token

方法：两个全新会话、同一句提示，一个装 OCMem 一个不装，从 OpenCode 的会话库里读 prompt token。

运行Prompt tokens
装 OCMem6,406
不装6,316
差值90

摘要块当时 169 个字符。加上常驻注册的 memory 工具 schema（约 100 token）， 单次总开销约 200 token。长会话里前缀会被缓存，实际计费更低。

三步用起来

需要 Node.js 18+ 和 OpenCode。数据全部存在本机 JSON 里。

  1. 安装插件
    在终端执行 opencode plugin add github:Fish303303/ocmem。
  2. 正常聊天
    说到长期偏好时会自动记下来，重复的会合并，不用手动整理。
  3. 需要时检索
    让 Agent 调 memory search <关键词>，或直接问“我之前说过什么”。
# 手动查看存了什么
opencode
memory list

# 检索
memory search 部署

# 删掉一条
memory forget <id>

它到底做了什么

自动捕获

只保留像长期偏好的陈述句，提问、一次性命令、测试闲聊都会被过滤。

去重合并

字符二元组 Jaccard ≥ 0.75 视为近似重复，自动合并成一条。

写入托管块

摘要写在 <!-- ocmem:begin --> 与 <!-- ocmem:end --> 之间，随时可手动清理。

短期回忆

保留上几次会话最后几条非提问消息，新会话能接着说，不用重述背景。
